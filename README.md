# Opus Optim (O2)

This is the Java 8 optimizer foundation for managed Minecraft 1.8.9, with a
host-neutral API/core, a local benchmark engine and a platform provider/callback
bridge checked against an archived Loader draft. Managed game wiring, installation
and controlled scenario runners remain pending. The first explicit experimental
candidate implements adaptive frustum corner tests for one pinned OptiFine M5
raw class;
no installed game optimization or measured game performance gain is claimed.

## Modules and verification

- `:api`: immutable descriptors, patch claims, capability/environment identity,
  activation/evidence enums, and measured-counter snapshots.
- `:core`: registry, configuration store, compatibility/planning decisions,
  and incomplete-launch recovery.
- `:bench`: bounded raw frame capture, strict JSONL run reports, exact percentiles/
  slowest-frame lows, independent-run A/A–A/B comparison and offline CLI.
- `:platform-opus`: sealed startup bindings/provider registrations and optional
  raw telemetry callback; compile-only Loader draft fixture is excluded from its JAR.

From this repository root:

```sh
./gradlew clean test check assemble
```

The pure API/core/bench `test` and `check` tasks run `verifyOptimBoundary`. It checks production
dependencies, Java source, and compiled symbols for forbidden game, Loader, UI,
and GL references. Opus Runtime retains its current five artifact roles; the
ordinary O2 Gradle JARs are not added to Launcher staging. Platform `test`, `check`
and `assemble` verify the JAR's SPI, Java 8 class version and absence of bundled
Loader/ASM/game classes; every build checks the archived Loader source hashes.

## Configuration

`ConfigStore` takes an explicit local path. Loading never writes a file. Missing
config leaves Optim OFF; invalid, oversized, wrongly typed, or unsupported-schema
config enters SAFE and refuses scoped updates without altering the existing file.
Updates reload the current document, retain unknown root fields/feature flags,
check for changes during the read/update, and replace through an atomic move.
Explicit null members are preserved. If the formatted output would exceed the
1 MiB read limit, the update fails and retains the original readable file.
There is no non-atomic overwrite fallback. Use one writer per config path; this
store is not a multi-process transaction or a shared-settings migration.

```json
{
  "schemaVersion": 1,
  "enabled": false,
  "features": {}
}
```

`updateFeature(id, enabled)` changes only that boolean flag;
`updateEnabled(enabled)` changes only the kill switch. Neither method silently
repairs a corrupt/future document. Unknown feature ids are preserved in config
but cannot become selected without a registered descriptor.

## Planning and trusted metadata

Descriptors are supplied by trusted, managed code, not discovered from arbitrary
mods. Their status is a **declaration**, not evidence generated by this core.
Only a declared `DEFAULT` can run without an explicit flag while Optim is ON;
experimental status/backends always require explicit opt-in. Assigning DEFAULT
remains conditional on the separately reviewed benchmark/parity gates.

Every registered id is either selected or excluded with a reason and an optional
fallback suggestion. Fallbacks never override explicit OFF or auto-enable an
unvalidated feature. Missing capabilities/dependencies, disabled dependencies,
cycles, rejected status and unproven patch composition are excluded before any
future platform registration. Unresolved conflicting eligible features are both
disabled; baseline Loader claims remain authoritative.

`PatchClaim` declares an exact class, method including descriptor, anchor, effect,
composition receipt id and relative order. A matching receipt and distinct orders
can compose instrumentation with behavior; competing behavior edits at the same
anchor remain rejected. Dependencies and composition order both constrain the
immutable selected-id list; contradictory ordering cannot be installed.

These are metadata checks, not bytecode-shape or receipt-authenticity validation.
The future platform must verify the pinned target/mapping/anchors and enforce the
claimed order against actual Loader transformer ordering, including baseline
claims. `restartRequiredComparedTo` compares the ordered startup metadata; it
does not unapply already installed transforms or provide a live policy API.

## Launch recovery and metrics

Read `CrashMarker.inspect()` before planning, then `begin(runId, experimentalIds)`
before entering the runtime. An unfinished run disables all experimental features
on the following launch. An unreadable/corrupt marker disables all Optim features
and preserves the base path. Inspection does not delete or rewrite the marker.
Use one active writer per marker path. Starting the next run replaces its previous
marker; `markCleanShutdown(runId)` refuses a different run id and must be called
only after the platform establishes a documented clean-termination criterion.
No first-frame or client-ready callback is treated as clean shutdown here.

`RuntimeDescriptor` never probes GL; `gl.*` capabilities require an explicit
completed platform probe. `Metrics` contains only provided nonnegative measured
counters and returns absence for unsupported/unmeasured values. Unit fixtures
use synthetic identities/counters; there are no real game samples, percentile
visual parity receipts, or VALIDATED/DEFAULT promotions in M1.

## Benchmark engine

`FrameCapture` is a single-writer, preallocated diagnostic sampler. Call `record`
with actual positive frame wall-duration nanoseconds, then `finish` with COMPLETE
or INTERRUPTED termination and only counters the caller has measured. It discards
declared warmup frames and counts overflow as dropped; it does not allocate or do
I/O per frame. `RunReports.writeNew` writes a new local JSONL file; an existing
file is never overwritten. A truncated or inconsistent report fails to load.

Inspect a report or compare four directories of independent session reports:

```sh
./gradlew :bench:run --args='stats /absolute/path/run.jsonl'
./gradlew :bench:run --args='compare /path/aa-control /path/aa-repeat /path/control /path/treatment /path/evidence.json'
```

`stats` prints scope/variant fingerprints, mean and nearest-rank p50/p95/p99,
plus exact 1%/0.1% lows when sufficient raw samples exist. Missing lows are null.
These are wall durations, not CPU-only cost, GPU time or allocation measurements.

`compare` requires at least five distinct process-session reports per arm and
1,000 complete, undropped frames/run. A/A and A/B control variants must match;
scope, sampling and warmup policy must match throughout. Every run has equal
weight, regardless of its duration. The comparator reports effect, A/A noise and
nominal uncertainty for run means and run-level p95/p99 aggregates. It rejects
proven tail regressions and refuses inconclusive/missing evidence. See the
[precise statistical assumptions and bounds](docs/BENCHMARK_SPEC.md).

Evidence JSON v1 contains `featureId`, `scopeFingerprint`,
`controlVariantFingerprint`, `treatmentVariantFingerprint`, plus `parity`,
`mechanism` and `compatibility` objects. Each object has `status` PASS/FAIL/MISSING
and `sha256` (null for MISSING; receipt hash otherwise). For example, a missing
parity receipt is `{"status":"MISSING","sha256":null}`. Receipt binding and
completeness are checked; receipt contents and session independence are supplied
declarations requiring an external review. Neither metadata nor unit fixtures
authenticate real game measurements.

Exit codes: 0 stats/PERFORMANCE_SIGNAL, 2 invalid input, 3 INCONCLUSIVE, 4 REJECTED.
Gradle forwards nonzero CLI exits as a failed JavaExec task; read the JSON verdict.
PERFORMANCE_SIGNAL is a screening result and never mutates the optimization
registry, enables a feature or assigns VALIDATED/DEFAULT. Synthetic-origin reports
remain INCONCLUSIVE even with a large computed effect. Actual game measurement,
instrumentation A/A overhead, controlled lobby/chunk fixtures and Loader integration
are the next work; this engine is not completion of those milestones.

## Loader handoff

O2 is a wider suite still in development; see the [current implementation map](docs/ENGINEERING_STATUS.md).
The new `PipelineOptimizations.candidates()` pack contains independent opt-in
font-glyph lookup, vertex-buffer growth and chunk-upload deadline candidates.
Retain each candidate's status handle and pass its binding to ProviderPlan.
If the host routes a raw class under a mapped identity, supply that exact name
through `candidate(kind, routingAliases)`; this never accepts remapped bytecode.
The [pipeline results](evidence/2026-10-14-pipeline/RESULTS.md) record actual M5
method-kernel parity, A/A/A/B font forks, allocation/copy savings with extra peak
capacity, and upload deferral with increased completion latency. None is managed
game installation, visual acceptance, FPS evidence or default promotion.

```sh
./gradlew :platform-opus:pipelineVerify -Pjava8Home=/path/to/java8/home -PminecraftJar=/path/to/1.8.9.jar -PoptifineJar=/path/to/OptiFine_1.8.9_HD_U_M5.jar
```

`ProviderPlan.prepare` maps trusted startup bindings to immutable exact-target
registrations, retains core exclusion reasons, checks Loader priority/id ordering
against dependencies/composition and verifies injected helper class identity.
`OptimBootstrap.install` is once-only before approved SPI discovery; discovery
seals even an unconfigured OFF snapshot.

`FrustumOptimization.candidate()` supplies the first actual candidate:
`render.frustum.positive-vertex`, EXPERIMENTAL and OFF without an explicit flag.
It preserves OptiFine M5 float behavior, first-corner success, disabled bypass and
full containment, then skips remaining corner tests when the supporting corner
settles an ordered box. Raw target SHA/capabilities/helper identity are required;
unknown or remapped input stays unchanged with an observable unsupported state.
Retain the returned candidate, pass its `binding()` to `ProviderPlan.prepare`,
and read its `applicationState()` after transformation. Each candidate owns its
status; startup selection alone does not establish application. APPLIED records
rewritten bytes, not class definition, game use or a performance gain.
There is no VALIDATED/DEFAULT promotion or managed game installation.
The [current query results](evidence/2026-10-13-frustum/RESULTS.md) include both
reductions on mixed/outside workloads and an inside-workload regression under
controlled JIT scheduling; promotion is refused. These are local query costs.

The [candidate spec](docs/FRUSTUM_CANDIDATE_SPEC.md) defines its exact scope.
Run real local-bytecode parity on Java 8, without committing vendor classes:

```sh
./gradlew :platform-opus:frustumVerify :platform-opus:writeFrustumHarnessClasspath -Pjava8Home=/path/to/java8/home -PminecraftJar=/path/to/1.8.9.jar -PoptifineJar=/path/to/OptiFine_1.8.9_HD_U_M5.jar
python3 scripts/frustum-microbench.py --java8-home /path/to/java8/home --minecraft-jar /path/to/1.8.9.jar --optifine-jar /path/to/OptiFine_1.8.9_HD_U_M5.jar --classpath-file platform-opus/build/frustum-classpath.txt --output /new/local/report-directory
```

The harness uses generated direct-call adapters, warmup, observable checksums,
and independent A/A/A/B JVM forks. Query-wall timings are local microbenchmarks,
not game-frame data or FPS. ASM 5.0.3 is compile-only and host-owned; it is never
bundled in O2. The host must include the compatible API before candidate creation.

`FrameTimingBridge.start` explicitly attaches one bounded diagnostic session.
The future host telemetry observer calls `frameCompleted` with its existing wall
interval; no new frame transformer or GL probe is added. Invalid/foreign-thread
callbacks invalidate the capture and requested COMPLETE becomes INTERRUPTED.
`CaptureSession.finish` detaches/seals; report output is explicit outside the loop.

The archived Loader draft currently rejects an approved empty OFF provider, and
its default adapters approve no O2 provider. These are demonstrated prerequisites,
not silently patched host behavior. See the [exact host handoff and baseline
protocol](docs/LOADER_HANDOFF.md) and [bridge spec](docs/PROVIDER_BRIDGE_SPEC.md).
Synthetic ASM/SPI tests do not prove a real game integration or baseline.

An additional executable artifact check requires an installed Java 8 VM:

```sh
./gradlew :platform-opus:java8Smoke -Pjava8Home=/absolute/path/to/java8/home
```

It uses the actual O2 JARs plus the separate API fixture and labels every report
SYNTHETIC. Gradle itself runs on the existing supported build JVM.
